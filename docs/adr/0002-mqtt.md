# ADR 0002: MQTT for device transport

Status: accepted for initial architecture.

Context: devices need lightweight publish/subscribe messaging, reconnect handling, and a broker-level identity boundary. HTTP telemetry is simpler operationally but less suitable for the chosen pub/sub device model.

Decision: use MQTT.js and Eclipse Mosquitto with topics `tenants/{tenantId}/devices/{deviceId}/telemetry`. Start local development with an isolated anonymous broker; require TLS, unique device credentials, and exact ACLs before production.

Consequences: broker operation and credential lifecycle become required infrastructure. QoS 1 can redeliver events, so server-side idempotency is mandatory. A payload cannot authenticate a device. Broker acknowledgments are not atomic with Firestore commits; define replay and crash recovery before promising durable ingestion.
